# Validation

What has actually been checked, how, and — just as importantly — what has not. rooler is alpha;
this page is meant to let you judge for yourself how much to trust each part.

Everything below was run on Linux 6.8, libhdf5 1.10.10, `cooler` 0.10.4, `cooltools` 0.7.1,
Python 3.12. Timings for the same runs are in [BENCHMARKS.md](../BENCHMARKS.md).

---

## Verified against the reference implementations

These compare rooler's output to `cooler`/`cooltools` on the same input, at real scale.

| what | how it was checked | result |
|---|---|---|
| `cload` | full pixel table vs `cooler cload pairs`, element by element | **byte-identical**: all 2,563,532,077 pixels of an ENCODE hg38 micro-C file at 256 bp, and all 26,345,683 pixels of a 50 M-pair subset at 10 kb |
| `coarsen` | every level vs `cooler zoomify`, bin counts and pixel counts | identical at 512 / 1024 / 2048 bp from a 2.5 B-pixel base |
| `coarsen` | total counts conserved through a 5-level cascade | exact: 484,364,054 over a 247 M-pixel chr1 slice, identical at 64/128/256/512/1024 bp |
| `balance` | bin mask vs `cooler balance` | **0 disagreements** at 10 kb (23,036 bins), 50 kb (58,261) and 256 bp (11,239,300) |
| `balance` | weights vs `cooler balance`, both fully converged | median **2.5e-6**, p99 3.4e-6 |
| `expected` | all 13 columns vs `cooltools.expected_cis`, incl. the log-smoothed ones | **2.7e-15** — machine precision, 0 NaN mismatches, whole-chromosome view |
| `expected` smoother | against values generated by `cooltools.sandbox.expected_smoothing.log_smooth` | pinned in a unit test |
| Python tables | `pixels`, `pixels(join=True)`, `bins`, `chroms` vs cooler's own accessors | identical frames, including dtypes and the ordered categorical `chrom` |
| file format | rooler output opened and fetched through `cooler.Cooler` at every scale up to 81 B pixels | opens; regions fetch correctly and symmetrically |
| gzip writer | direct-chunk output vs HDF5's own filter pipeline | pixel-identical, same advertised filter pipeline |
| gzip reader | both write paths decoded through the parallel reader | identical, including the partial edge chunk |

### Known, deliberate divergences

Not bugs, but you should know they exist.

- **Balance stopping rule.** At each tool's default, weights differ by ~2e-4: rooler stops on a
  scale-free criterion (`CV = std/mean < 1e-4`), cooler on an absolute variance threshold. Set
  `--tol` to match and they agree to 2.5e-6 (above).
- **Bins straddling a region boundary.** Where an arm boundary falls inside a bin — possible at
  some resolutions, never for a whole-chromosome view — `cooltools` counts that bin in `n_valid`
  but omits it from the sums; rooler includes it in both. Brute-force summation over the pixel
  table agrees with rooler. Affects ~4% of rows by ~0.2% for an arms view.
- **`.pairs` coordinates are read as 1-based** (the 4DN spec, and cooler's default). Use
  `--zero-based` for a file that genuinely is not.

## Verified by the test suite

`cargo test --release` (49 tests, ~1 s) and `pytest python/tests` (8 tests). Both generate their
own data — no network, no fixtures, no reference files.

- **End-to-end pipeline** (`tests/pipeline.rs`): synthetic pairs → cload → merge → zoomify →
  balance → expected, each stage compared against an independent in-test oracle — a brute-force
  recomputation, not a stored answer. Includes a marginal-flatness property check for balance,
  agreement between the row-chunk and cache-blocked kernels to 1e-9, and an O(n²) recomputation
  of expected.
- **Determinism**: cload output is byte-identical across `--mem` and `--threads` settings
  (0.0005 GB / 1 thread vs 4 GB / 8 threads).
- **Codecs**: round-trip tests for every compressed intermediate, including the u8/exception
  count boundary, `i32::MAX`, and spill runs spanning multiple blocks.
- **Merge semantics**: aggregation across sources, duplicate-key runs spanning block boundaries,
  empty and degenerate inputs, emit-block invariance.
- **Ranged readers**: range partitions reproduce the full key stream exactly, including
  duplicate keys straddling block boundaries.
- **Guard rails**: mystery coolers refused, mismatched merges refused, out-of-range pairs
  positions refused, counts saturating rather than wrapping, `expected` on an unbalanced cooler
  refused, `ooe` across a region boundary refused.
- **`repack`**: rewrites in place and to `--out`, preserving the pixel table, the weights, and
  any extra `bins/` columns (checked against a cooler carrying `GC` and a non-default weight).
- **Unsupported variants refused**: a `storage-mode: square` cooler is rejected by name rather
  than silently mis-read.

## Not tested

Be appropriately suspicious of these.

**Not supported, and refused with an explanatory error** (each verified against a cooler built
by `cooler` itself with that feature):
- **Asymmetric (`storage-mode: square`) coolers.** The kernels assume the upper triangle.
- **Variable-width bins (`bin-type: variable`).**
- **Float counts.** rooler stores `int32` and would truncate them.

**Not implemented at all**
- **Trans expected.** `expected` is cis-only; `ooe` therefore refuses trans fetches.
- **KR balancing.** Only iterative correction; no cis-only or per-chromosome variants.
- **`.scool`** (single-cell) files.
- **`.pairs` fields beyond chrom/pos.** No filtering on strand, pair type or mapping quality —
  do that upstream (e.g. with `pairtools`).

**Implemented but unverified**
- **`balance` at 100-billion-pixel scale.** Never run. It is the one op that holds a compressed
  matrix rather than streaming, so it is bounded by `--mem` and spills to a disk-backed map
  beyond that; the spill path is tested only at small scale.
- **Downstream `cooltools` analyses.** Only `expected_cis` has been compared. Pileups,
  insulation, eigenvectors and saddles have never been run on a rooler file.
- **Consumers other than `cooler`/`cooltools`/`h5py`** — HiGlass, Juicer converters, R packages.
  The files are ordinary coolers so they ought to work, but nobody has checked.
- **Genomes outside the built-in table.** `expected`'s default view is baked in for a short list
  (human, mouse, fly, worm, yeast and a few named aliases); centromere positions exist only for
  hg38, hg19 and sacCer3. Anything else needs an explicit `--view`, and the arm coordinates for
  the supported genomes are approximate.
- **Reading coolers written by other tools**, beyond cooler itself. In particular `lzf`-
  compressed coolers cannot be read at all (no standalone HDF5 plugin exists); recompress them
  with `rooler repack` or cooler first.

**Environment**
- Linux x86-64 only. Never built or run on macOS, Windows, or ARM.
- libhdf5 1.10.10 only. The direct-chunk read and write paths use `H5Dread_chunk` /
  `H5Dwrite_chunk`, which need ≥ 1.10.3; other 1.10/1.12/1.14 builds are untested.
- Single process at a time. Concurrent writers to one file are not supported, and a rooler op
  cannot open a file that a live read handle holds open in the same process.

## Reproducing

```bash
cargo test --release                       # Rust suite
pytest python/tests                        # Python accessor suite (needs cooler)

scripts/validate_vs_cooler.py a.cool b.cool   # compare two coolers pixel-for-pixel at any scale
scripts/validate_vs_cooler.py a.cool --self-check   # verify a file reads through cooler

SRC=big.cool PAIRS=big.pairs.gz scripts/bench_2p5b.sh /tmp/bench   # head-to-head vs cooler
scripts/bench_vs_cooler.sh sub.pairs.gz /tmp/bench 8
```
